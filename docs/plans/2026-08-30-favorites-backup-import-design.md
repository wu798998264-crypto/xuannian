# 收藏备份与跨设备导入优化设计

## 目标

让“收藏导出”只生成可跨设备迁移的收藏备份，并保证玄念能直接导入 ZIP、立即刷新界面、准确报告导入结果。

## 数据范围

新版备份只包含普通收藏相关数据：收藏分类、收藏条目、便签、灵感分类、灵感条目，以及这些内容实际引用的附件。剪切板历史 `records`、剪切板图片缓存 `clipboard-images`、截图缓存、拖拽缓存、媒体下载与媒体库收藏、设备路径和快捷键设置均不导出。

媒体库收藏继续使用独立目录管理，不混入“剪切板收藏储存路径”下的收藏备份按钮。

## 文件格式

继续使用 ZIP。包内包含：

- `manifest.json`：格式标识、版本、导出时间、内容数量；
- `favorites-data.json`：仅收藏相关的结构化数据；
- `assets/`：仅复制被收藏内容实际引用的附件。

导出先写入同目录的 `.part` 文件，压缩完成并确认非空后再原子替换最终 ZIP，避免远程软件在导出过程中读取到 0 字节占位文件。

## 导入兼容与刷新

导入器优先读取新版 `manifest.json` 和 `favorites-data.json`，同时兼容旧版包含 `xuannian-data.json` 的备份。旧包导入时只选取收藏字段，忽略剪切板历史和设置。附件复制到当前设备的收藏资源目录，并把包内相对路径重写为当前设备绝对路径。

导入完成后发送完整数据刷新事件，渲染器重新读取收藏、便签和剪切板状态；不再调用不存在的 `loadData()`。成功提示显示实际新增或合并的收藏数量，空包或格式错误会返回明确原因。

## 验证

1. 用测试快照导出，断言 ZIP 数据不包含 `records` 和设备设置。
2. 断言只收集收藏引用的附件，不包含无关剪切板缓存。
3. 将新版包导入空数据快照，核对分类、收藏、便签和附件路径。
4. 将旧版全量备份导入，断言剪切板记录不会进入目标设备。
5. 运行现有性能与 Electron 运行时回归测试。
