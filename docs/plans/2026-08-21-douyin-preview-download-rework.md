# 抖音预览、下载与媒体库分类重做计划

> 状态：待确认。确认前只做研究，不执行代码修改、安装或发布。

## 1. 现状结论

当前仓库发布基线仍是 `v9.1.3`（`ff6964e`）。工作区存在上一轮未发布的 `v9.1.4` 草稿改动，但它不能作为已验证版本直接继续交付；执行时先审阅并与本计划合并，保留用户已有的无关改动。

旧日志已经证明过一条可用链路：下载站真实按钮触发 `will-download`，捕获 `aweme.snssdk.com/aweme/v1/play/` 媒体地址，流式写入临时文件，再用于预览或移动到 `视频` 目录。该链路曾成功完成约 52 MB 的抖音视频下载和预览。

现在的失败链路有两个确定问题：

1. DLPanda 的解析说明页、输入页按钮或站内地址被当作下载候选，HTTP 响应实际是 `text/html`，所以既不能生成视频预览，也不会产生下载文件。
2. 临时预览文件第一次被移动后，后续点击仍会重新跑解析和下载候选；重新跑到错误候选时，界面显示“下载”但下载任务没有真实文件。

## 2. 推荐实现方向

采用“单次解析、单次捕获、缓存复用”的会话状态机，不再把每个按钮点击当成一次新的解析任务：

```text
抖音链接
  -> DLPanda 解析
  -> 只接受真实媒体源/真实下载弹窗
  -> 写入 media-preview-cache 临时文件
  -> video 标签从 file:// 临时文件预览
  -> 下载/收藏：移动同一个临时文件到目标目录
```

解析结果、预览状态和正式下载状态分开。预览失败只更新预览状态，不清空解析结果，也不阻断正式下载。视频已缓存时，“下载”和“收藏”只执行本地移动/复制，不重新请求网络。对于没有直链的“备用下载”，保留为手动打开下载站，不把解析页地址伪装成自动下载地址。

直接媒体 URL 校验会补齐抖音真实 CDN 形态（包括 `snssdk.com/aweme/v1/play/`），并同时校验 HTTP 状态、响应类型和首包内容，明确拒绝 HTML/JSON。移除“把页面地址交给 `downloadURL` 作为兜底”的路径；只有真实按钮产生的下载弹窗才允许进入捕获流程。为避免预览和下载并发读同一源，增加同一解析会话的一次性捕获锁和缓存路径状态。

## 3. 媒体库图片分类处理

推荐只删除媒体库顶部的“图片”媒体类型和对应的下载/收藏分类，不删除应用其他地方的图片能力：剪贴板图片、便签图片、全盘图片搜索和附件预览保持不变。历史 `图片` 目录中的文件不主动删除，升级后不再出现在媒体库分类列表中。

解析结果中的“封面图片”建议保留，但把它视为当前视频的附属下载项：封面由已缓存视频生成，保存到当前视频的下载/收藏目标中，不再创建独立的媒体库“图片”分类。这样既保留之前约定的封面能力，也不会重新引入一个用户不需要的图片媒体库入口。

### 任务三：实现捕获缓存会话

文件：`src/main.js`。

- 解析完成后创建唯一会话，记录 `sourceUrl`、真实媒体源、临时路径、预览状态和已移动目标。
- 优先使用解析结果中的原生视频源；否则只点击一次真实视频下载按钮并拦截 `will-download`，将完整可用视频写入临时目录。

- 下载任务只有在真实媒体传输开始后才入列表，避免出现“显示下载但列表没有文件”。

## 5. 验收标准

- 抖音解析结果不会因预览失败而消失，解析失败与预览失败在 UI 上分开。
- 预览成功时使用临时缓存文件；点击下载或收藏不重复下载，目标目录出现且只出现一个完成任务。
- 任意 HTML/JSON/解析页地址都不会被写入视频文件或进入下载列表。
- 备用下载不误报自动成功，手动打开仍可用。
- 媒体库类型只剩“视频”和“音乐”；剪贴板、便签、附件和全盘图片搜索不受影响。
- 构建、安装、仓库版本和更新检查链路全部通过。
